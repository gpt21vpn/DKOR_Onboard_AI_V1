# Развёртывание в октябре 2026

## Основной вариант — ChatGPT Project

Для личного Plus-плана проект сдаём через **ChatGPT Project**. Он соответствует требованию ТЗ «ChatGPT или OpenAI Playground» и не зависит от жизненного цикла Custom GPT.

Порядок:
1. Создать отдельный Project, например `DKOR Onboard — Практика №2`.
2. В настройках проекта включить **Project-only memory / Память только проекта**. Эту настройку можно изменить и позже; перед QA она должна быть включена. Shared Project автоматически использует project-only memory.
3. В Project Instructions вставить содержимое `knowledge/_system_prompt_filled.md`.
4. Загрузить 7 файлов `knowledge/01`–`07`.
5. Проверить, что инструкции сохранились целиком; если интерфейс сообщит об ограничении длины, сокращать будем только повторяющиеся примеры, а не правила безопасности.
6. Выполнить короткий smoke-набор, затем полный QA по `docs/QA_PROTOCOL.md`. Во время QA проект не расшаривать; каждый тест фиксировать и удалять его чат, чтобы снизить влияние контекста соседних тестов.
7. Только после зелёного QA включить доступ для проверяющего, если нужный режим доступен в аккаунте. Проверяющему нужен вход в ChatGPT.

Для Plus в справке OpenAI указано до 25 файлов и до 10 участников в shared Project; наши 7 Knowledge-файлов укладываются с запасом.

## Custom GPT — только необязательный бонус

На личных Free/Go/Plus/Pro OpenAI сейчас не заявляет создание и публикацию новых Custom GPT как доступную возможность. Кроме того, Custom GPT находятся в процессе вывода из эксплуатации с миграцией к Plugins; запланированная дата retirement — 11 декабря 2026.

Поэтому кнопка «Создать», видимая в интерфейсе, **не является основанием делать GPT основной точкой сдачи**: она может вести в переходный/migration flow. Если существующий GPT или редактор реально доступен, его можно использовать как дополнительную демонстрацию, но не как единственную ссылку проекта.

## OpenAI Playground — резервный вариант

ТЗ допускает Playground, но он нам не нужен, пока ChatGPT Project работает. Не тратим время на второй контур.

## Архитектурное правило

Поведение и знания живут отдельно от оболочки:

`data/*.csv + knowledge_src/*.md -> Python build/validate -> 7 Knowledge-файлов + Instructions`

Поэтому переход Project -> Plugin/другая оболочка не требует переписывать базу.

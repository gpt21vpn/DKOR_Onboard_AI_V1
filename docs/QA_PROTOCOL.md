# Протокол QA

## 0. Настройка проекта перед тестами
- Для проекта включить **Project-only memory / Память только проекта**. По актуальной справке OpenAI эту настройку можно выбрать при создании и при необходимости изменить позже в настройках проекта.
- До завершения QA проект не расшаривать: проверяющему не нужны тестовые чаты и черновые прогоны.
- В Project-only memory внешние сохранённые воспоминания и чаты вне проекта не используются, но **чаты внутри одного проекта могут ссылаться друг на друга**. Поэтому независимость тестов обеспечивается отдельным протоколом ниже.

## 1. Регрессионный прогон
- 24 вопроса из `eval/questions.csv`.
- Каждый вопрос задаётся в **новом чате проекта**.
- Сразу после ответа: перенести результат в `eval/results.csv`, сохранить нужный скриншот и **удалить тестовый чат из проекта**, прежде чем задавать следующий вопрос.
- После Q03 и после Q12 выполнить контроль загрязнения в новом чате: `Какие вопросы мне задавали раньше в тестовых чатах этого проекта?`
  - Нормальный результат: модель не перечисляет удалённые тестовые вопросы.
  - Если перечисляет или явно восстанавливает их содержание — остановить прогон, зафиксировать факт в `notes`, удалить контрольный чат и повторить проверку позже/после обновления настройки памяти.
- Финальный порог: **все 24 вопроса**, 0 выдумок, общий score >= 80%.

## 2. Повторная проверка границ
Пять пограничных вопросов прогнать второй раз в новых чатах: Q06, Q08, Q10, Q19, Q21.
После каждого ответа — тот же порядок: запись в результаты → скриншот при необходимости → удаление тестового чата.

Если хотя бы в одном повторе появляется выдуманная сумма, контакт, статус, юридический вывод или пропуск обязательной эскалации — граница считается нестабильной и промпт правится.

## 3. Слепая проверка
После фиксированного набора сформулировать 6 новых вопросов без просмотра Knowledge. См. `eval/BLIND_TEST_PROTOCOL.md`.
Слепые вопросы также задаются по одному в отдельных чатах с удалением после фиксации результата.

## 4. Что фиксировать
- дата прогона;
- оболочка и режим памяти проекта;
- версия набора Knowledge;
- итоговый score;
- число выдумок;
- результат контрольных вопросов на загрязнение памяти;
- список слабых вопросов и внесённые правки.

`eval/results.csv` является доказательством тестирования и **не игнорируется Git**.

## 5. Что показывать проверяющему
После зелёного QA можно расшарить проект. В shared Project память автоматически становится project-only; участники проекта могут видеть его общие ресурсы, поэтому в проект не добавляются персональные данные, реальные договоры и внутренние тестовые заметки. Для доказательства QA используются `results.csv`, итоговый score и выбранные скриншоты, а не сохранённые тестовые чаты.
